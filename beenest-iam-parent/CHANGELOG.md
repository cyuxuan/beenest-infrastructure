# 变更日志

版本号遵循 [语义化版本](https://semver.org/lang/zh-CN/)。本文件记录对外可见的能力与行为变更;
内部重构与坏味道修复记录在 `docs/code-review-2026-10.md`。

## [Unreleased] - 2026-10-31

安全审查与链路闭环:补齐登出、授权码、令牌验签、管理面与联邦通道的缺口。逐条记录见
[`docs/security-review-2026-10-31.md`](./docs/security-review-2026-10-31.md)。

### 发布镜像瘦身与分层

- **镜像从 456MB 降到 356MB**:`Dockerfile.release` 去掉了 `apt-get update && upgrade`。
  它曾被当作"打补丁"写进构建,实际只多出一层约 100MB 的整包替换、构建多花两分钟,
  而补丁有效期也只到下次重建。基础镜像本就自带 DejaVu 字体(验证码画图依赖)、
  时区数据与 `curl`,不需要额外安装。
- **业务代码与依赖分层**:jar 用 Spring Boot 的 tools 模式在宿主拆成
  `dependencies`(85MB,依赖升级才变)与 `application`(1.7MB,每次改代码都变)两层,
  推送时只需上传变化的那一层。分层后容器内是"普通 jar + 外部 lib",
  启动改用 `-cp` 而非 `java -jar`。

### 授权失败可诊断

- **400 不再显示「系统内部错误」**:授权端点 400 多为回调地址与登记值不一致,新增
  `page.error.400.*` 文案(中/英),眉标 `REQUEST REJECTED`,提示点明协议、域名、端口、路径
  必须逐字相同。
- **被拒请求写 WARN**:格式 `请求被拒绝: status= uri= caller= detail=`,400 额外带查询串;
  `detail` 是授权服务器的真实判定码(`invalid_request`、`invalid_redirect_uri` 等)。
  新增 `caller` 字段(X-Forwarded-For 首段 + 截断的 User-Agent),用于识别探测、健康检查
  与遗留在其他系统的旧地址。
- **修复客户端删不掉**:`countReferences` 的 `session_count` 只数 `iam_client_session` 行,
  不看用户会话是否已结束,强制下线后仍提示「在线会话 1 条」。改为关联 `iam_user_session`
  判断 `state = 'ACTIVE'` 且未过期。

### 令牌受众可填、可查错

- **中文输入法下回车能加标签了**:标签控件此前在 `keydown` 里见 `Enter` 就提交并 `preventDefault`,
  而输入法未上屏时的回车本是"确认候选词",两边抢同一个按键,表现就是「按回车没反应」。
  现在先判断 `isComposing`(及 `keyCode === 229`),让输入法消化后再处理。
- **说明改成照着做**:「令牌受众」补 placeholder 与口径——输入一个值后按回车(别用逗号连写),
  多个值逐个添加;留空则自动用 `urn:iam:app:{应用编码}`,详情页会显示派生出的实际值。
- **错法在保存前就拦住**:前端口径校验 + 服务端 `validateAudiences` 双道;逗号/中文标点连写、
  夹带空格、超长超量都会被明确拒绝,不再出现"看着填了两个、其实存成一个"的静默故障
  (这种故障下令牌照常签发,只是每次调用都被资源服务器按受众不匹配拒掉)。

### 登出真正生效

- **门户退出不再落到无权限页**:退出表单的 CSRF 字段名此前取成了请求头名(`X-XSRF-TOKEN`),
  而服务端按参数名 `_csrf` 取值,校验失败即 403,表现为"点退出后进入无权限页"。字段名改由
  页面内嵌的 `parameterName` 决定,令牌缺失时回落到 CSRF Cookie。
- **登出会吊销已签发的令牌**:新增会话级吊销标记,访问令牌携带 `sid`,验签环节据此拒绝。
  此前登出只删会话快照,访问令牌在到期前一直可用、刷新令牌还能继续换票。
- **统一登出入口**:`/logout`、`/logout-all`、管理端下线、撤回同意、SAML 单点登出全部走
  `IamLogoutService`,不再各自结束会话;撤回同意同时吊销授权记录。

### 授权码与令牌校验

- **授权码严格一次性**:并发换票只有一个请求成功。抢占标记按请求计数——同一次请求内
  PKCE 校验与换票各查一次授权,按查询计数会把正常流程判成重放。
- **校验令牌签发方**:验签后比对 `iss` 与 `{基址}/realms/{realmKey}`。
- **停用域不再接受令牌**:域停用后其此前签出的令牌立即失效。

### 管理面

- **权限特批受操作者权限上限约束**:授出与撤销都不得超出操作者自身权限。
- **不允许修改当前登录账号的角色**。
- **应用工作台只能改角色名称与启用状态**:归属由路径决定,不能把本应用角色提升为域角色。
- **SCIM 纳入平台令牌闸门**:业务应用令牌不能借 `scim:manage` 读写用户与组。
- **回调地址写入时校验**:必须绝对 `http(s)`、不含英文逗号(库内逗号分隔存储)。
- **LDAP 地址只接受 `ldap(s)://`**,拒绝链路本地与元数据地址。

### 联邦与外部通道

- **联邦 state 绑定浏览器**:发起时写入 Cookie,回调时比对,堵住"把受害者登成攻击者账号"。
- **联邦发起端点限流**:单来源 30 次/分钟。
- **SAML 单点登出不可伪造**:未验签的 LogoutRequest 只能结束当前浏览器自己的会话,
  不能按 NameID 结束该主体全部会话;LogoutRequest ID 加一次性。
- **凭据直换授权码拒绝要求二步验证的客户端**:这条链路不经过登录页,拿不到第二因素。

### 其他

- 短信验证码的错误次数上限此前是死代码(每次取码只有一次机会),改为先比对后删、达上限作废。
- 短信与口令重置的 IP 限流不再在来源未知时共用同一个桶。

### 配置

- **`iam.issuer-base-url` 生产必须显式配置**,见 [`docs/deployment.md`](./docs/deployment.md) §7。
- **本地 compose 宿主端口改为 8090**(容器内仍是 8080,`IAM_PORT` 可覆盖)。8080 常被本机
  其他服务占用,让开会把那些请求打到 IAM 上。依赖方 `issuer` 需同步为同一地址。

## [Unreleased] - 2026-10-30

应用角色授权闭环修订:角色可见范围、应用角色直授、令牌 `app_roles` 构成与控制台权限判定。

### 门户启动改为纯导航

- **门户不再代发授权地址**:`POST /api/v1/launchpad/apps/{appCode}/launch` 移除,改为
  `GET /portal/launch/{appCode}` 返回 302。`state`、`nonce`、`code_challenge` 的验证方都是应用,
  门户生成的值应用无法校验,强制 PKCE 时更无从生成——代发的结果是应用要么跳过校验,
  要么拒绝回调,表现为"点进去先报未登录、刷新一次才好"。现在授权请求完全由应用发起。
- **一个应用只有一个启动地址**:门户 302 到 `entryUrl`,其余交给应用。不引入"单点发起端点"
  这类第二地址:能给 `/sso/start` 的应用同样能让入口页自己 302,纯静态单页应用两边都给不出,
  多一个字段只多一处多数时候空着、空着就把卡片判成不可进入的配置。原 `sso_self_initiated`
  布尔标记移除(V1.3.6 / U1.3.6)。
- **入口地址保存时校验**:非空时必须 `http(s)` 开头,避免把浏览器送到跳不过去的地址。
- **卡片改为 `launchable` + `launchHint`**:卡片不再下发跳转地址,跳转由服务端在点击时判定。
  判定集中在 `LaunchPlanner`,卡片与跳转共用同一份 `LaunchPlan`。

### 令牌受众支持多个

- **应用可登记多个受众**:管理端「令牌受众」由单行文本改为多值输入,签发时全部写入 `aud`;
  只有一个时按 JWT 惯例序列化为字符串,多个时为数组。用于令牌需同时被网关与后端接受、
  或受众标识迁移期新旧并存。
- **接口字段改为 `audiences`(数组)**:`ApplicationServiceCreateRequest` / `UpdateRequest` /
  `Response` 的 `audience` 由 `String` 变为 `List<String>`;库内仍以英文逗号分隔存储,
  存量单值无需迁移。受众最多 5 个、单个不超过 200 字符、不含英文逗号(V1.3.7 / U1.3.7)。

### 变更

- **角色列表默认返回全部容器类型**:`GET /api/v1/admin/roles` 不传 `containerType` 时
  同时返回域角色、应用角色与客户端角色;应用角色在控制台按所属应用分组展示,
  用户授权弹窗也因此能看到并保留已分配的应用角色。
- **应用角色可直接授予用户**:`SCOPED` 应用的访问令牌 `app_roles` 取
  "映射结果 ∪ 直授的本应用应用角色",应用角色按角色码原样下发,不必再为每个角色建映射;
  服务端拒绝缺少所属应用的应用角色。`LEGACY_GLOBAL` 保持原声明不变。
- **映射来源仍限用户组与域角色**:应用角色是终态授权,不参与映射链。
- **控制台权限判定收紧**:移除前端对 `*` 通配符的隐式放行;空权限账号实测无任何管理菜单入口,
  并补充"空权限角色不产生兜底权限"的回归测试。

### 错误页与授权闸门

- **403 无权访问应用页重做**:深色蜂巢底纹 + 金色徽章,大号状态码水印,按 401/403/404/500
  切换眉标、标题与处理建议;应用授权闸门拒绝时点名被拒绝的应用,并给出
  "联系所属身份域管理员开通权限或加入用户组/角色"的明确指引,中英双语。
- **应用可见性闸门与客户端仓储同口径回落**:全局 `/oauth2/authorize` 不带域前缀时
  按 `default` 域判定,与客户端解析保持一致;修复"猜一条全局授权路径"绕过可见性拿到授权码。
  客户端准入过滤器的补验判定同样回落,登录方式与 MFA 要求不再被全局路径跳过。
- **错误页直接访问归位**:无错误上下文的 `GET /error`(错误页上的语言切换链接)
  重定向回入口页,不再把一次正常的语言切换显示成 500。

### 账户待办

- **待办办完后不再停在空页面**:改密会递增令牌版本、当前会话随即失效,刷新与重新登录
  都会带着 `return_to=/required-action` 回到待办页;待办已清空时直接跳转门户,
  不再让用户自己再登出登入一次。页面上的"所有待办均已完成"空态一并移除。

### 应用授权与门户可见性

- **修复可访问角色保存报"授权主体不存在于当前身份域"**:角色删除后其应用授权行未清理,
  弹窗回读名单时原样带回已删除的角色 id,整表覆盖保存被校验拒绝。现在删除角色会在
  同一事务内清理授权行,回读名单也会过滤已删除主体的历史记录,存量脏数据在下次保存时自然清掉。
- **应用角色即该应用的访问权**:持有某应用的应用角色即视为被应用管理员纳入该应用,
  门户启动台可见并可进入,无需再补一条授权记录;令牌受众回退同样受益。
  `PUBLIC` 与 `PERMISSION` 可见性口径不变。
- **应用授权弹窗区分域角色与应用角色**:候选按"域角色 · 全部应用可用"和
  "本应用角色 · 仅本应用"分组;其他应用的应用角色不再进入候选。服务端同步收紧,
  应用角色只能授权给所属应用,错误提示点名角色所属应用。

### 控制台复制

- **客户端密钥复制修复假成功**:非 HTTPS 部署下 `navigator.clipboard` 不存在,复制走
  `execCommand` 回退;临时输入框落在对话框外,焦点陷阱把焦点抢回面板,选中内容丢失,
  命令仍返回 true 并提示"已复制",粘贴为空。临时输入框改为带 `data-focus-exempt` 标记、
  由焦点陷阱放行,复制结束把焦点还给原元素;提示文案只在写入确认后为成功,
  失败时提示手动复制并自动选中密钥文本。
- **安全上下文走 Clipboard API**:`https` 与 `localhost` 使用 `navigator.clipboard.writeText`,
  其余场景统一走选中复制回退。

### 客户端与角色的配置纠错

- **客户端删除不再被自身作用域分配挡住**:`iam_client_scope_mapping` 是客户端自己的配置项
  (只服务于管理端勾选回显,运行时鉴权读 `iam_client.scopes`),此前被计入"下游引用",
  勾过作用域就永久删不掉。现在它不计入引用,并在删除时随客户端一起清理。
- **删除受阻时逐类报数**:错误信息由"仍被 2 条下游数据引用"改为按类别给出条数与解除入口
  (授权同意 / 在线会话 / 客户端角色 / 应用绑定),不再让运维猜去哪解除。
- **新增客户端类型变更**:`POST /api/v1/admin/clients/{id}/type`。类型决定令牌端点认证方式,
  不并入通用更新;仅"从未产生客户端会话、无授权同意"的客户端允许变更。
  降级为公开客户端会清空密钥并强制 PKCE,与 `client_credentials` 冲突时拒绝;
  升级为机密客户端现场签发新密钥,明文只在响应中返回一次;两个方向都记审计。
- **角色归属可在"干净"时变更**:`PUT /api/v1/admin/roles/{id}` 接受
  `containerType / appServiceId / clientId`。归属决定授权面(有效角色解析不按容器过滤),
  因此只在角色未被用户/组/岗位分配、未授予权限与菜单、无应用授权时允许变更,
  并校验目标作用域下角色编码唯一;已承载授权关系的角色会拒绝并给出条数。

**通知与发信**

  按 RFC 2696 分页读取目录(突破 AD 单次 1000 条限制),只补建缺失账号、补全空缺资料,

  "被顶下线"与"超时失效";策略读取失败时放行登录(可用性优先)。

### 安全加固(2026-10-28 安全演练)

本地 Docker 环境按"认证 / 业务 / 镜像 / 依赖"四条线做了演练,修复项如下:

- **CSRF Cookie 加固**:`XSRF-TOKEN` 写入 `Secure` 与 `SameSite=Lax`,与 `IAM_SESSION`
  的标记保持一致,防止明文信道与跨站携带;`iam.session.cookie-secure=false` 仅供本地 HTTP 调试。
- **安全响应头补全**:协议链与业务链统一下发 `Referrer-Policy: same-origin` 与
  `Permissions-Policy`(关闭摄像头、麦克风、定位、支付、USB 等未使用能力)。
  这里不能用 `no-referrer`:真实浏览器对表单提交的 `Origin` 由 referrer 推导,
  referrer 被清空后 `Origin` 会退化成字面量 `null`,服务端拿不到真实来源,
  同源登录会被判成跨源并返回 `Invalid CORS request`。
- **验证码生成限流**:`/api/v1/auth/captcha` 按来源 IP 限制每分钟 60 次,
  挡住批量刷图与"识别后继续撞库";超限返回 429。
- **依赖漏洞修复**(以漏洞扫描结果为准,均升级到含修复的版本):
  Tomcat `11.0.24 → 11.0.25`(4 项 CRITICAL,含 FORM 认证绕过)、
  BouncyCastle `1.80.2 → 1.85`(名称约束绕过 / ASN.1 拒绝服务)、
  Jackson 2 `2.21.5 → 2.21.7`、Jackson 3 `3.1.5 → 3.1.7`、
  httpcore5 `5.3.6 → 5.4.3`、Guava `33.0.0-jre → 33.7.2-jre`、
  Velocity `2.3 → 2.4.1`(不再内嵌带 CVE 的 commons-io)。
- **镜像构建**:运行阶段执行 `apt-get upgrade` 吸收系统库补丁(openssl 等);
  删除 `EXPOSE 9090`,避免 `docker run -P` 把管理端口一并映射到宿主机。
- **本地编排**:`compose.yaml` 的 PostgreSQL / Redis 只绑 `127.0.0.1`,并加
  healthcheck;该文件仅用于本地开发,不用于生产。
- **文档**:部署文档新增第 10 节"容器与部署安全基线",并补充反向代理的转发头信任边界
  与 HSTS 下发位置。

### 安全修复(2026-10-29 应用授权与会话)

- **授权端点补应用可见性闸门**:客户端绑定应用服务后,`/oauth2/authorize` 校验当前账号对该应用可见
  (与门户共用 `ApplicationVisibilityService`),不可见返回 403 并记 `APPLICATION_ACCESS_DENIED` 事件。
  此前门户可见性只挡住"从门户点进去",知道 `client_id` 与回调地址即可绕过;
  未绑定应用的客户端(平台自身、机器对机器)不受影响。灰度开关
  `iam.authorization.enforce-application-visibility`,默认 `true`。
- **凭据登录同口径校验**:`/api/v1/auth/provider-code`(小程序等)不经过授权端点,现补同一判定,
  不可见返回 403(`20003`)。
- **同浏览器重复登录结束旧会话**:浏览器关闭不会结束服务端会话,同一浏览器再次登录时它带来的
  旧会话置为 `REPLACED` 并删除 Redis 快照;不同账号、不同设备上的会话互不影响。
- **一次登录只签发一个会话**:表单登录的认证过滤器在成功处理器之前会保存一次安全上下文,
  会话上下文仓库此前借此补建会话,导致一次登录落两条记录,其中一条没有登录事件、
  Cookie 被覆盖后无人使用,在「在线会话」里长期显示为在线。会话签发现统一由登录会话服务完成。
- **会话列表按 Redis 订正状态**:管理端「在线会话」与用户自助会话列表以 Redis 快照为准,
  已失效但数据库行未巡检的行显示为已过期,不再显示成在线。
- **收回 USER 直授即收回既有访问**:移除应用的用户直授时,事务提交后吊销该用户在该应用上的
  授权记录(访问令牌进黑名单、刷新令牌失效),只向该应用投递后通道登出并关闭对应的客户端会话。
  不再出现"后台已收回、已打开的应用还能继续用";其它应用与 IAM 会话不受影响。
- **刷新令牌复核应用可见性**:`/oauth2/token` 刷新时按库中当前授权关系重新判定,用户已无权时
  返回 `invalid_grant`。这是角色/组授权收回的兜底,避免仅靠已签发令牌续期绕过收回。
  与授权端点共用开关 `iam.authorization.enforce-application-visibility`。

### 新增(2026-10-29 微信手机号登录)

- **小程序手机号登录**:`wechat-mini` 提供方支持 `phoneCode`(手机号快速验证组件的一次性 code),
  由提供方调用微信手机号接口换取号码,作为**已验证手机号**交给平台;提供方配置新增
  `phoneLoginRequired`(默认开启),开启后缺少 `phoneCode` 直接拒绝登录(400)。
  手机号只认服务端换取结果,客户端上送的号码不参与判定。
- **账号按已验证手机号归并**:三方登录解析顺序改为 已有绑定 → 已验证手机号 → 新建账号。
  本地已存在同号且已验证的账号(HR 导入、管理端预建)时直接接管并写入绑定,不重复建号;
  已绑定账号本地无手机号时补写,已有号码保留不动。同一手机号并发登录时后到者归并,不再报错。
- **SPI 扩展**:`BrokeredIdentityContext` 增加 `verifiedPhone`;`UserProvider.createFederatedUser`
  增加手机号参数,并新增 `updateVerifiedPhone`。平台核心不理解微信语义,只提供通用能力。
- **错误语义拆分**:小程序提交的 `jsCode` 无效或已被使用返回 401(`20001`),
  微信侧配置与网络类错误仍是 502(`20013`),避免把用户操作问题报成上游故障。

### 新增(2026-10-29 访问令牌受众指向应用)

- **应用受众配置**:「应用门户 → 应用服务」新增「令牌受众」,该值写进本应用访问令牌的 `aud`;
  留空按 `urn:iam:app:{app_code}` 派生,存量应用升级后自动获得按应用隔离的受众,无需逐条回填。
- **同一后端多入口共享受众**:Web 端与小程序是两个客户端、两条应用服务时,把两条记录的受众
  填成同一个值,资源服务器只校验这一个值就能同时接受两个入口的令牌。
- **收回应用授权即时改变受众**:解绑应用后令牌的 `aud` 落回 `client_id` 且 `token_kind=PLATFORM`,
  应用侧 Spring Security 内置的 `JwtAudienceValidator` 直接拒绝,应用不需要改配置重新发版。
  ID Token 与后通道登出令牌的 `aud` 不变,仍按 OIDC 规范等于 `client_id`。
- **受众自动回退**:客户端未绑定应用时,若用户恰好被授权一个应用(经角色、直授或组),
  令牌自动使用该应用的受众,避免管理员必须配置客户端绑定。多个或零个授权时回退到平台令牌。

### 行为变更(升级需注意)

| 变更 | 影响 | 处理方式 |
|---|---|---|
| 小程序登录默认要求 `phoneCode` | 只传 `jsCode` 的客户端升级后被拒(400) | 客户端补手机号授权;或在该提供方配置 `phoneLoginRequired=false` |
| 访问令牌 `aud` 改为应用受众 | 按 `aud == client_id` 校验的应用升级后被拒 | 改为校验本应用登记的受众(未配置时是 `urn:iam:app:{app_code}`);ID Token 的 `aud` 仍是 `client_id` |

## [1.0.0] - 2026-10-27

首个可对外投产的版本。相对内部开发基线(0.0.1-SNAPSHOT)的变更如下。

### 新增

**协议与接入**
- **SAML 2.0 IdP 模式**:本平台作为企业 IdP 向存量应用签发断言,端点
  `/realms/{realmKey}/saml/{metadata,sso,slo}`。签名证书由域密钥确定性派生,
  重启与多实例不漂移。详见 `docs/saml-idp.md`。
- **SCIM 2.0**:`/scim/v2/Users` 与 `/scim/v2/Groups`,支持 `filter`(`eq` / `co`)、
  分页、`PUT` 与 `PATCH`(RFC 7644 PatchOp),鉴权权限码 `scim:manage`。
  详见 `docs/scim.md`。
- **Passkey / WebAuthn**:设备本地密钥登录,可作一级凭据,含签名计数器克隆检测。
  详见 `docs/passkeys.md`。
- **国际化**:中英双语覆盖全部协议页与错误码,语言解析顺序 显式选择 → Cookie →
  浏览器偏好 → 默认中文。详见 `docs/i18n.md`。

**账号与自助**
- **账户自助**:找回口令(邮件链接 / 短信验证码)、邮箱验证、账户待办
  (`UPDATE_PASSWORD` / `VERIFY_EMAIL` / `CONFIGURE_TOTP`)。详见 `docs/account-self-service.md`。
- **用户中心 `/account`**:账号资料、登录凭证、我的授权、登录设备、个人数据导出。
  详见 `docs/account-center.md`。

### 安全

- **令牌类型分流**:ID Token 不再携带 `permissions` 声明,并写入 `token_type=id`;
  解码链拒绝以 ID Token 充当 Bearer 令牌。
- **管理接口令牌类别限制**:`/api/v1/admin/**`、`/api/v1/console/**`、`/api/v1/launchpad/**`
  只接受浏览器会话与平台类令牌(`token_kind` 为 `PLATFORM` / `MACHINE`);
  业务应用令牌(`APPLICATION`)一律拒绝,堵住 `LEGACY_GLOBAL` 令牌越权调用管理接口。
- **CSRF 豁免判据收紧**:`Authorization: Bearer` 前缀不再豁免,必须令牌验签通过才豁免。
- **来源校验**:状态变更请求要求 `Origin`/`Referer` 为本站或已登记前端来源,
  覆盖登录类接口的登录 CSRF 风险。
- **口令哈希升级为 Argon2id**,保留 `{bcrypt}` 兼容;移除 `{noop}` 支持。
- **身份域租户隔离**:非平台域管理员只能查看与修改自身域;建域、删域、轮换签名密钥
  仅平台域管理员可执行(平台域由 `iam.platform-realm-key` 指定,默认 `default`)。
- **客户端删除引用检查**:存在授权同意、在线会话、作用域分配、客户端角色或应用绑定
  时拒绝删除,不再留悬空引用。

### 行为变更(升级需注意)

| 变更 | 影响 | 处理方式 |
|---|---|---|
| 存量口令为 `{bcrypt}`,新口令为 `{argon2}` | 用户下次改密时自动升级,登录不受影响 | 无需处理 |
| 移除 `offline_access` 支持 | 客户端登记含该 scope 时被拒绝;存量数据由 `V1.3.0` 清理 | 需要长期令牌的场景改用较长 `refresh_token_ttl`,并接受"会话结束即失效" |
| ID Token 不再含 `permissions` | 若有应用从 ID Token 读权限码,需改为读访问令牌或调 userinfo | 检查接入方的权限来源 |
| 业务应用令牌不能调 IAM 自身接口 | 应用侧若曾用用户令牌调 `/api/v1/console/**`,会得到 403 | 改为由应用自己提供等价功能 |
| 身份域管理收敛到平台管理员 | 租户管理员不能再改其它域 | 需要跨域管理时使用平台域账号 |
| 删除客户端需先解除引用 | 有同意/会话/作用域/角色/应用绑定时删除失败 | 先清理引用,或改为停用(`enabled=false`) |
| 版本号 `0.0.1-SNAPSHOT` → `1.0.0` | 制品坐标变化 | 重新 `mvn install`;镜像重新构建 |
