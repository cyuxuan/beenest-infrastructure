# 国际化(i18n)

中英双语,覆盖全部协议页与错误码。管理控制台前端(Vue SPA)不在此范围内。

## 1. 语言解析顺序

```
?lang=zh-CN / ?lang=en   →   Cookie IAM_LOCALE   →   浏览器 Accept-Language   →   默认中文
   显式选择(最高)              跨请求保持              首次访问照顾             兜底
```

实现见 `club.beenest.iam.common.i18n.IamLocaleResolver`:

- 只认 `zh` / `zh-CN` / `en` / `en-US` 四种写法(大小写、`_` 与 `-` 均可),其余一律视为"没选"
- Cookie 名 `IAM_LOCALE`,`path=/`,有效期 365 天,`HttpOnly`(语言偏好不需要 JS 读)
- 浏览器偏好只区分"是不是英文",其它语言一律落到中文——没有对应翻译的目录展示出来仍是中文

`LocaleChangeInterceptor` 只接受 GET 请求上的 `lang` 参数,避免接口的 POST 顺带改掉用户偏好。

## 2. 文案键约定

| 前缀 | 用途 |
|---|---|
| `error.{错误码}` | 与 `ErrorCode.defaultMessage` 一致,改这里即改所有接口的错误提示 |
| `page.brand.*` / `page.common.*` | 品牌名、页脚、返回登录、语言切换、网络异常等通用文案 |
| `page.login.*` | 登录页;`page.login.js.*` 为该页内联脚本用的提示 |
| `page.mfa.*` | 二步验证页 |
| `page.challenge.*` | 补充验证(准入挑战)页 |
| `page.consent.*` | 授权同意页;`page.consent.scope.{scope}.{label,desc}` 为 scope 释义 |
| `page.error.*` | 错误页,按 HTTP 状态码分支 |
| `page.forgot.*` / `page.reset.*` / `page.verifyEmail.*` | 找回口令 / 重置口令 / 邮箱验证 |
| `page.action.*` | 账户待办;`page.action.name.{CODE}` 与 `page.action.desc.{CODE}` 按动作代码取文案 |

占位符用 `{0}` `{1}`,页面上写 `#{key(参数)}`。**脚本里用的占位符不会被服务端替换**,而是原样注入后由 JS 的 `fmt()` 填值——见第 4 节。

## 3. 三层取文案的方式

**页面(`th:*`)** —— 直接 `th:text="#{page.login.welcome}"`。需要动态键时用 `#messages.msg('key')`,不要写 `#{${key}}`。

**静态工厂(`Result` / `BusinessException`)** —— 这两个类拿不到容器,走 `IamMessages`:

```java
public static Result<Void> fail(ErrorCode code)          // 按当前请求语言取 error.{code}
public static String message(String key, Object... args)  // 任意键
```

`IamMessages` 在 `IamI18nConfiguration#messageSource` 里注册一次(静态 `volatile` 字段),之后全局只读。**未注册时全部回落 `ErrorCode.getDefaultMessage()`**——单元测试、批处理、命令行工具因此不需要起容器。

**控制器自拟文案** —— 注入 `MessageSource`,用 `messageSource.getMessage(key, null, 兜底, LocaleContextHolder.getLocale())`。

### 可翻译与不可翻译

`BusinessException` 有三个构造器,区分了两种文案:

```java
new BusinessException(ErrorCode.X)                    // messageLocalizable = true
new BusinessException(ErrorCode.X, "该密钥已绑定过账号")  // messageLocalizable = false
new BusinessException(code, message)                  // messageLocalizable = false
```

`GlobalExceptionHandler` 据此决定:`true` 时重新按语言解析错误码文案;`false` 时原样输出调用方给的那句话——因为那句话通常带着上下文(哪个字段、哪条记录),翻译它只会让信息变少。

## 4. 页面内联脚本的文案

脚本块必须声明 `th:inline="javascript"`,文案用注释包裹的字面量形式:

```html
<script th:inline="javascript">
    var MSG = {
        codeRequired: /*[[#{page.mfa.js.codeRequired}]]*/ '请输入动态口令',
        networkError: /*[[#{page.common.networkError}]]*/ '网络异常,请稍后重试'
    };
</script>
```

- `/*[[...]]*/` 里的内容在服务端渲染时被替换成对应语言的 **JS 字符串字面量**(自动加引号、转义)
- 注释后面的字面量是**兜底**:直接用浏览器打开静态 HTML、或模板内联未启用时仍能跑
- 带占位符的文案(`page.login.js.ssoButton=使用 {0} 登录`)由 `fmt(template, value)` 在运行时替换

## 5. 语言切换入口

`themes/{theme}/fragments/lang-switch.html` 里的 `switch` 片段,由 `IamPageModelAdvice` 注入的 `langSwitch` 模型驱动:

| 字段 | 含义 |
|---|---|
| `label` | 目标语言的**自称**(中文界面显示 `English`,英文界面显示 `中文`) |
| `url` | 切换后的地址:沿用当前路径与查询参数,**只替换 `lang`** |
| `targetTag` | 目标语言标签,用于 `hreflang` / `lang` 属性 |

保留原查询参数是必须的:登录页带着 `client_id` / `return_to`,同意页带着 `state`,丢参数会让用户切一次语言就掉出授权流程。

新增页面时把片段挂上即可:

```html
<div class="iam-lang-row">
    <a th:replace="~{(${themeName} + '/fragments/lang-switch') :: switch}"></a>
</div>
```

## 6. 新增文案

1. 在 `beenest-iam-common/src/main/resources/i18n/messages.properties` 加键(**中文是兜底文件**,必须先加)
2. 在 `messages_en.properties` 加同名键
3. 页面用 `th:text="#{key}"` 引用,兜底文案写在标签体里(自然模板,静态打开也能看)

英文文件缺键不会报错,会自动回落中文——这样"只翻了一半"的构建也不会出现空白提示或裸键名。

## 7. 新增语言

1. 加 `messages_{tag}.properties`(如 `messages_ja.properties`)
2. 在 `IamLocaleResolver` 的 `SUPPORTED`、`parseTag`、`toTag` 三处加上该标签
3. 在 `IamPageModelAdvice#langSwitch` 里把"二选一"改成按当前语言挑下一个(目前是中英互切)

第 3 步是有意留的:只有两种语言时,一个"切到另一种"的按钮比下拉菜单少一次点击。

## 8. 验证

- `ThemeTemplateRenderingTest`(web 模块)—— 用真实模板引擎把 9 个协议页在中英两种语言下各渲染一遍,断言文案随语言切换、片段引用可解析、脚本占位符原样保留
- `IamLocaleResolverTest` / `IamMessagesTest`(common 模块)—— Cookie 优先级、浏览器回落、不支持标签、Cookie 写入参数;静态门面在"未注册文案源"时回落错误码默认文案

模板只在运行时渲染,编译期发现不了语法错误与缺失的键,这几组测试是提交前的唯一防线。

## 9. 已知边界

- **管理控制台前端未做 i18n**:Vue SPA 自成体系,与协议页的两套资源不共用;控制台使用者是内部管理员,优先级低于对外登录页
- **邮件正文未做 i18n**:邮件在异步线程发送,取不到请求语言;要支持需给邮件模板传入收件人的语言偏好
- **错误码文案与 `ErrorCode.defaultMessage` 需手工保持一致**:前者是展示文案,后者是 API 返回的兜底,两者不联动
