## 支付服务从 CAS 客户端切换为 IAM 资源服务

**目标**：支付服务以标准 OAuth2 资源服务接入 IAM（`/Users/sunny/Desktop/dev/beenest/beenest-iam-parent`），
同时移除对 `club.beenest.cas` 构件源的全部依赖。

**依赖**：父 pom 删除 `beenest-cas.version` 与 `club.beenest.cas:beenest-cas-client-resource-server-starter` 依赖管理；
service pom 改为 `spring-boot-starter-oauth2-resource-server`。

**新增（`club.beenest.payment.config` / `security`）**：
- `IamResourceServerProperties`（前缀 `iam.resource-server`）：audience、user-id-claims、require-application-token、
  auto-provision-wallet、wallet-biz-type、reject-inactive-wallet；`@PostConstruct` 把 claims 顺序注入 `AuthUtils`。
- `IamJwtAuthenticationConverter`：permissions→原样 authority、scope→SCOPE_*、realm/client/app_roles→ROLE_*。
- `JwtAudienceValidator`、`IamAccessTokenValidator`（拒绝 ID Token，可选强制 token_kind=APPLICATION）。
- `PaymentUserAdmissionFilter`（order = SecurityProperties.DEFAULT_FILTER_ORDER+10，仅 `/api/wallet/**`、`/api/customer/**`）：
  首次访问自动开通钱包、钱包非 ACTIVE 返回 403，替代原 CAS 访问控制 SPI。

**改写**：`PaymentSecurityConfig`（oauth2ResourceServer + 自定义 JwtDecoder，端点取
`spring.security.oauth2.resourceserver.jwt.issuer-uri`/`jwk-set-uri`）、`AuthUtils`（改为读 JWT claims，
openid 从 `idp_identities` 兜底匹配 wechat 渠道）。

**删除**：`PaymentAccessControlService`（CAS SPI 实现）、`PaymentCacheConfig`（只为 CAS 缓存而存在）。

**配置**：`nacos-config/beenest-payment*.yml`、`application-{dev,test,prod}.yml`、`.env` 全部改为
`IAM_ISSUER_URI` / `IAM_AUDIENCE`，移除 `cas.*` 与 `CAS_*` 变量。

**测试**：`AuthUtilsTest` 改为 JWT 上下文；新增 `IamJwtDecoderTest`（本地 HttpServer 模拟发现文档 + JWKS，
覆盖验签/受众/ID Token/issuer 四种场景）。`mvn -o -pl beenest-payment-service test` 49 个测试全绿。

**注意**：Flyway 迁移 `V1_0_9__wallet_customer_profile.sql` 注释里仍有 CAS 字样，未改动（避免破坏 checksum）。
本地 5432 端口是 IAM compose 的 postgres（beenest/secret123），无 beenest_payment schema，故未能做完整启动冒烟。

## 补充：customer_no 锚点定稿（用户确认「按最优设计，不考虑历史」）

- **钱包 `customer_no` 固定 = IAM `uid`**，不取 `sub`（`sub` 跟随身份域/客户端的「主体标识」策略，
  默认是登录名，改名即变，会导致同一账号开出第二个钱包）。
- 删除 `iam.resource-server.user-id-claims` 配置项与 `AuthUtils.configureUserIdClaims` 静态注入，
  claim 名以 `AuthUtils.USER_ID_CLAIM` 常量唯一表达，避免配置漂移。
- `IamAccessTokenValidator` 增加第 3 条校验：`uid` 缺失即 `invalid_token`（401），不做任何回退。
- `PaymentUserAdmissionFilter` 建户时把令牌 `nickname` / `phone_number` 写入钱包档案
  （原 CAS SPI 的画像同步语义）。
- 建议 IAM 侧把该客户端主体标识切到 `USER_ID`，使 `sub` 与 `uid` 同值，跨系统关联口径一致。
- 测试：`IamJwtDecoderTest` 增加「缺 uid 拒绝」，`AuthUtilsTest` 增加「缺 uid 不回退 sub」；50 个测试全绿。
