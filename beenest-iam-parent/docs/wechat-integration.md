# 微信登录接入指南

本文覆盖两种微信登录形态：**小程序登录**（小程序后端直传凭据）与**扫码登录**（微信开放平台网站应用）。

两种形态都由同一个扩展包 `beenest-iam-provider-wechat` 提供，平台核心不含任何微信相关的知识。

---

## 1. 两种登录形态

| 形态 | 提供方类型 | 交互方式 | 所需凭据 |
| --- | --- | --- | --- |
| 小程序登录 | `wechat-mini` | 小程序后端把凭据直送平台，换授权码 | `jsCode`（`wx.login()` 的一次性 code）+ `phoneCode`（手机号授权的一次性 code，默认必填） |
| 扫码登录 | `wechat-web` | 浏览器跳到微信扫码授权页，微信回调平台 | 无（浏览器流程） |

> 凭据的**键名由提供方自己定义**：平台只把客户端提交的参数原样转交，不解释其含义。因此别的第三方想接自己的小程序，改自己的扩展包即可，平台不用改。

---

## 2. 扩展包的热插拔

### 2.1 交付形态

微信扩展包打成一个独立 jar，放进平台的**外置扩展包目录**即可生效：

```
providers/
└── beenest-iam-provider-wechat-1.0.0.jar
```

配置项（环境变量 `IAM_PROVIDER_DIR`，默认 `./providers`）：

```yaml
iam:
  provider:
    dir: ./providers
```

> 服务端主包**不再内置**微信扩展包。运行镜像在构建时把本仓库构建出的扩展包复制到镜像内
> `/app/providers`（与 `IAM_PROVIDER_DIR` 一致），容器部署开箱即可用；源码部署或替换版本时，
> 把上面这个 jar 放进 `iam.provider.dir` 指向的目录。目录里没有 jar 时，平台只认识协议本身，
> 不认识 `wechat-mini` / `wechat-web` 两个提供方类型。

### 2.2 生效方式

- **启动时扫描**外置目录，逐个装载 jar 里的提供方工厂（`META-INF/services` 服务声明）。
- 装好后**重启平台**即生效：类一旦加载就无法卸载，不重启无法换掉扩展包内容。
- 目录不存在表示不启用外置装载，不影响内置提供方。
- 某个 jar 装载失败只记错误日志，**不影响平台启动**（第三方包坏了不该让整个平台起不来）。

### 2.3 第三方扩展包怎么写

扩展包只依赖两样东西（`provided` 作用域，不打进交付 jar）：

- `beenest-iam-core`：提供方 SPI（`IdentityProvider` / `IdentityProviderFactory`）。
- `beenest-iam-federation`（可选）：复用 `OAuth2IdentityProvider` 基类拼授权地址。

jar 内的结构：

```
META-INF/services/club.beenest.iam.core.spi.federation.IdentityProviderFactory
  → 一行一个工厂实现类的全限定名
```

工厂实现类要求：

- **有无参构造**（服务声明只能这样实例化）。
- 声明配置项（`getConfigProperties`）与管理端配置表单、必填校验都由它驱动。
- 声明登录形态（`getLoginModes`）：`REDIRECT`（浏览器跳转）/ `CREDENTIAL`（凭据直传）。
- 若提供凭据直传形态，再声明自定义授权类型（`getGrantType`）。该值只作**类型元数据**用于管理端展示与
  重名校验，不是令牌端点上的可用 grant：凭据登录统一走 `/api/v1/auth/provider-code`，换令牌仍用标准
  `authorization_code`。

## 3. 小程序登录接入

### 3.1 微信侧准备

1. 微信公众平台创建小程序，拿到 **AppID / AppSecret**。
2. 在「开发管理 → 服务器域名」里把**小程序自己的后端域名**加入 request 合法域名。
   小程序前端只调自己的后端；IAM 由后端服务端调用，不需要出现在小程序的合法域名里。

### 3.2 平台侧配置

管理端 → 身份提供方 → 新建：

- 提供方类型：**微信小程序**（`wechat-mini`，扩展包注册的类型）
- 别名：如 `wx-mini`（域内唯一，登录时用别名指定）
- 小程序 AppID：小程序的 AppID
- 小程序 AppSecret：小程序的 AppSecret（加密落库、不回显）
- 必须授权手机号（`phoneLoginRequired`）：默认开启。开启后登录必须同时提交 `phoneCode`，
  平台用它在微信侧换取手机号；关闭则退回仅按 `openid`/`unionid` 建号

> **类型与别名不是一回事**：`wechat-mini` 是扩展包声明的提供方类型，所有小程序共用；
> `wx-mini` 是你在本域给这套 AppID/AppSecret 起的别名。下面的接口里 `provider` 字段传的是**别名**，
> 不是类型。一个域可以配多个不同 AppID 的小程序，各用各的别名。
>
> **扩展包引入 ≠ 生效**：必须配齐必填项才能启用。管理端会在保存时校验必填配置，缺失会直接拒绝并指明缺哪一项。

### 3.3 客户端调用（两步）

前置条件（任一不满足都会在第一步被拒）：

- 客户端是**机密客户端**：接口要求 `clientSecret`，公开客户端没有密钥，用不了这条链路；
- 客户端授权类型包含 `authorization_code`；
- 客户端已绑定应用服务，否则换到的令牌只有身份声明（`token_kind=PLATFORM`）、没有权限码。

> **绑定应用同时带来可见性门槛**：客户端绑定应用服务后，凭据登录会校验该账号对该应用可见
> （`PUBLIC` / 权限码 / 授权名单三者之一），不可见返回 403（`20003`）。标准授权码流程在
> `{issuer}/oauth2/authorize` 上做同一判定；灰度期可用
> `iam.authorization.enforce-application-visibility=false` 临时关闭。

**第一步：凭据换授权码**

```
POST {平台地址}/api/v1/auth/provider-code?realm={域标识}
Content-Type: application/json

{
  "provider": "wx-mini",
  "credentials": {
    "jsCode": "<wx.login() 拿到的 code>",
    "phoneCode": "<手机号快速验证组件回调里的 code>"
  },
  "clientId": "<客户端标识>",
  "clientSecret": "<客户端密钥>",
  "codeChallenge": "<客户端要求 PKCE 时必填：code_verifier 的 S256 摘要>"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `provider` | 是 | 提供方**别名**（不是类型 `wechat-mini`） |
| `credentials.jsCode` | 是 | `wx.login()` 的一次性 code |
| `credentials.phoneCode` | 条件 | 手机号快速验证组件的一次性 code；提供方开启「必须授权手机号」时必填 |
| `clientId` / `clientSecret` | 是 | 客户端凭据，只在后端使用 |
| `codeChallenge` | 条件 | 客户端开启「强制 PKCE」时必填；省略会被拒（400） |

> **手机号只认服务端的换取结果**：平台不接收客户端直接上送手机号，只接收 `phoneCode` 并调用
> 微信手机号接口换取号码。这样写进本地账号的手机号一定是微信侧的已验证号码，客户端无法伪造。

成功响应是平台统一的 `Result` 包装，业务数据在 `data` 里：

```json
{
  "code": 0,
  "message": "成功",
  "data": {
    "code": "b7c9xQ...",
    "redirectUri": "https://mini-api.example.com/iam/callback"
  },
  "success": true,
  "timestamp": 1792469359000
}
```

- 取 `data.code` 与 `data.redirectUri`，**不要**按顶层 `code` 取授权码（顶层是业务码，0 表示成功）；
- `redirectUri` 固定取客户端登记的**第一个**回调地址；客户端没登记回调时回落
  `urn:ietf:wg:oauth:2.0:oob`。因此换码地址要登记为唯一或第一个回调地址；
- 授权码 5 分钟内有效、一次性使用。

**第二步：标准授权码换令牌**

```bash
curl -X POST '{平台地址}/realms/{域标识}/oauth2/token' \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  -d 'grant_type=authorization_code' \
  -d 'client_id=<客户端标识>' \
  -d 'client_secret=<客户端密钥>' \
  -d 'code=<data.code>' \
  -d 'redirect_uri=<data.redirectUri>' \
  -d 'code_verifier=<开启 PKCE 时的原始 verifier>'
```

响应是标准 OAuth2 令牌响应：`access_token` / `token_type` / `expires_in` / `scope`；
客户端登记了 `refresh_token` 时还有 `refresh_token`，`scope` 含 `openid` 时还有 `id_token`。
之后用 `Authorization: Bearer <access_token>` 调平台接口；刷新走标准 `grant_type=refresh_token`；
吊销走标准 `/oauth2/revoke`。

**错误对照**

| HTTP | 业务码 | 文案/场景 | 处理 |
|---|---|---|---|
| 400 | 10001 | `小程序登录缺少 jsCode`、`小程序登录缺少 phoneCode`、`该客户端要求 PKCE,凭据登录必须携带 code_challenge` | 补参数；PKCE 客户端先算挑战值 |
| 401 | 20001 | `微信小程序登录凭证已失效`（`jsCode` 无效或已被使用） | 重新 `wx.login()` 取新 code 后重试 |
| 401 | 20001 | `客户端凭据无效` | 核对 clientId / clientSecret |
| 401 | 20001 | `该客户端未获授权使用授权码流程` | 给客户端补 `authorization_code` grant |
| 401 | 20006 | `账号已禁用或锁定` | 联系管理员 |
| 403 | 20003 | `账号无权访问应用: xxx` | 该账号对客户端绑定应用不可见:调可见性(改 `PUBLIC` / 按权限码 / 加授权名单),或换绑其他客户端 |
| 404 | 10002 | `身份域不存在`、`身份提供方不存在: xxx` | 核对 `realm` 与提供方**别名** |
| 409 | 10003 | `该外部身份已绑定其它账号`、`该手机号账号已绑定同一提供方的其它外部身份`、`外部身份对应的本地登录名已存在` | 在用户管理中解绑或改名后再登录 |
| 409 | 10004 | `身份提供方已停用: xxx` | 管理端启用该提供方 |
| 429 | 10005 | 同一 IP 超过 60 次/分钟，或同一客户端密钥错误超过 20 次/分钟 | 退避后再试，不要循环重试 |
| 502 | 20013 | 微信接口不可用、AppID/AppSecret 错、响应缺 openid、手机号接口报错 | 查平台日志与微信侧配置。`errcode` 属配置类（如 40013 无效 AppID、40125 无效密钥）时按这条排查 |

**调用方式与限流**

- **只在后端调用**：接口要求 `clientSecret`，小程序前端直接调等于把长期凭据打进包里；
- 该接口豁免 CSRF，但**带未登记跨源 `Origin` 的请求会被来源校验拒绝（403）**。
  服务端到服务端调用通常不带 `Origin`，不受影响；
- 失败会写登录事件（`loginType=PROVIDER`），可在管理端「登录事件」按客户端标识排查。

> **PKCE**：客户端登记为「强制 PKCE」时，第一步带 `codeChallenge`（`code_verifier` 的 S256 摘要），
> 第二步带对应的 `code_verifier`；挑战值固定按 `S256` 处理，不支持 `plain`。

### 3.4 客户端登记

平台管理端 → 客户端 → 新建：

- 客户端类型：**机密客户端**（小程序后端持有密钥）
- 回调地址：填后端换码地址。凭据登录固定使用**第一个**回调地址，所以把它放在第一条
- 授权范围：`openid`（需要昵称档案再加 `profile`）
- 应用绑定：在「应用门户」把该客户端绑定到一个应用，否则令牌只有身份声明

授权类型与 PKCE 的登记方式：

- 客户端表单默认授予 `authorization_code` + `refresh_token`，小程序场景够用；
- 控制台**没有**授权类型勾选项。若需调整（例如只留 `authorization_code`、或加 `client_credentials`），
  用管理接口 `POST/PUT /api/v1/admin/clients` 的 `grantTypes` 字段；
- 「强制 PKCE」开关在客户端表单里，打开后第一步必须带 `codeChallenge`。

> **准入策略对这条链路不生效**：客户端的 `allowedLoginTypes` / `requireMfa` 只在
> `/oauth2/authorize` 判定，凭据登录不经过授权端点。小程序场景若需要限制登录方式或强制 MFA，
> 要在业务后端自行校验。

## 4. 扫码登录接入

### 4.1 微信侧准备

1. 微信开放平台申请**网站应用**，完成企业认证（认证有费用与周期要求）。
2. 拿到网站应用的 **AppID / AppSecret**。
3. 在开放平台登记**授权回调地址**：平台的 `https://{域名}/broker/{域标识}/{别名}/callback`。

> 授权回调地址必须与平台实际回调地址完全一致，域名、路径、协议都不能差。

### 4.2 平台侧配置

管理端 → 身份提供方 → 新建：

- 提供方类型：**微信扫码登录**（`wechat-web`）
- 别名：如 `wx-web`
- 开放平台 AppID / AppSecret
- 其余端点保持默认（微信公网地址）

### 4.3 使用

登录页会出现「使用 微信扫码登录 登录」的入口，点击后浏览器跳到微信扫码授权页；用户用微信扫一扫并确认，微信回调平台，平台换身份、建号、建立会话后回到应用。

> 扫码授权页由微信域名提供，**不能嵌进 iframe**，也不能在微信内置浏览器里打开（微信会提示在外部浏览器中打开）。

## 5. 账号归并与自动注册

### 5.1 解析顺序

每次登录按以下顺序确定本地账号，命中即止：

1. **已有绑定**：该外部身份（提供方 + `unionid`/`openid`）已绑定本地账号，直接复用。
   本地账号手机号为空、而本次登录取得已验证手机号时，补写该手机号；本地已有手机号时保留原值。
2. **按已验证手机号归并**：没有绑定，但本地已存在同一手机号且已验证的账号（HR 导入、管理端预建、
   其它渠道建号），直接接管该账号并写入绑定关系。
3. **新建账号**：以上都没命中才建新号。

> 用户直接拿手机号登录、而 IAM 里还没有这个号时，会走第 3 步：按微信换回的手机号建号，
> 手机号以**已验证**状态落库，不需要任何人预先授权或手工建号。之后同一微信用户再登录，
> 会在第 1 步命中绑定，不会重复建号。
>
> 归并只认微信侧换回的已验证号码；客户端上送的手机号字段不参与判定。

### 5.2 自动注册细节

- 首次登录自动建号，登录名规则：`{提供方别名}-{外部标识}`（如 `wx-mini-oAb1Cd2`）。
  外部标识里非 `A-Za-z0-9._-` 的字符会被替换为下划线；超长时截断并追加摘要后缀，保证登录名合法且域内唯一。
- 例外：账号已存在同名的本地账号且手机号也对不上时，登录报 409 并提示先改名或解绑，不静默改写已有账号。
- 外部标识：优先 `unionid`，没有则用 `openid`。
  - 同一微信用户在**小程序**与**开放平台**下的 `openid` 不同、`unionid` 相同。
  - 只有当小程序**已绑定到同一个开放平台账号**时，两边才会都拿到 `unionid`，从而被认出是同一个人；否则是两个账号。
- `openid` / `unionid` 随外部身份属性一并写入本地账号的扩展属性，可在管理端用户详情里直接看到。
- 外部身份与本地账号的绑定关系单独存放，删除提供方会解绑但**不删账号**。
- 同一手机号并发登录时，后到的请求归并到先建出来的账号，不会因唯一索引冲突直接失败。

## 6. 机密配置

- `clientSecret` / `appSecret` 这类键（**以 `Secret` 结尾**）在管理端保存时加密落库，**响应里只回键名不回值**。
- 编辑时留空表示「保持原值」，填写则覆盖。
- 其余配置项是整体覆盖：编辑时没填的键会被删掉。

## 7. 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 登录页没有微信入口 | 提供方未启用，或类型未注册（扩展包没装/没放到 `providers` 目录） | 检查管理端提供方状态；看启动日志里「已装载外置身份提供方扩展包」那行 |
| 点了入口提示「未接入的身份提供方类型」 | 扩展包没被装载 | 确认 jar 在 `iam.provider.dir` 指向的目录；重启平台 |
| 保存提供方报「必须配齐以下配置项」 | 必填项没填（AppID / AppSecret 等） | 按提示补齐 |
| 凭据接口返回 200，但把顶层 `code` 当授权码 | 响应有 `Result` 包装 | 取 `data.code` 与 `data.redirectUri` |
| 凭据接口 404「身份提供方不存在」 | `provider` 传成了类型 `wechat-mini` | 改传管理端配置的**别名** |
| 凭据接口 403 | 请求带了未登记的跨源 `Origin` | 从后端调用，或在 `iam.cors.allowed-origins` 登记该来源 |
| 凭据接口 429 | 同 IP 超过 60 次/分钟，或同客户端密钥错误超过 20 次/分钟 | 退避，不要循环重试 |
| 凭据接口 401「未获授权使用授权码流程」 | 客户端 `grantTypes` 缺 `authorization_code` | 用管理接口补该 grant |
| 换令牌返回 `invalid_grant` | 授权码过期（5 分钟）、已被用过、或 `redirect_uri` 与签发时不一致 | 用 `data.redirectUri` 原样回传；一次一码 |
| 令牌端点 `invalid_client` | 客户端密钥不对，或用了未登记的客户端 | 核对客户端标识与密钥；密钥只在创建/轮换时返回一次 |
| 换令牌成功但权限为空 | 客户端未绑定应用服务 | 管理端把客户端绑定到对应应用；平台按「未绑定应用只输出身份声明」的默认策略收敛权限 |
| 扫码页空白 | 授权地址参数不合规 | 平台侧拼装已保证 `appid` 在首位并带 `#wechat_redirect`；若自行改过端点请还原 |
| 小程序报 code 失效 | `jsCode` 只能用一次且 5 分钟内有效 | 每次登录重新 `wx.login()` 取新 code |
| 小程序报 400「缺少 phoneCode」 | 提供方开启了「必须授权手机号」，客户端没提交手机号授权 code | 小程序先调手机号快速验证组件拿到 `code`，与 `jsCode` 一起提交；或关闭该配置项 |
| 小程序报 401「登录凭证已失效」 | `jsCode` 已被使用、超时，或不是当前 AppID 签发的 | 重新 `wx.login()`；确认小程序 AppID 与提供方配置一致 |
| 登录成功但手机号为空 | 提供方关闭了「必须授权手机号」 | 开启后重新登录；已绑定账号会在下次登录补写手机号 |
| 手机号登录又建出一个新账号 | 本地同号账号未标记已验证，或号码不一致 | 归并只认已验证手机号；在用户管理里核对号码与验证状态 |

## 8. 已知边界

- **扫码登录依赖微信开放平台企业认证**，未认证时该提供方不可用。
- **小程序手机号登录依赖手机号快速验证组件**：需要小程序主体具备该能力；无法开通时可关闭
  「必须授权手机号」，退回仅按 `openid`/`unionid` 建号，账号不再与手机号关联。
- **手机号是跨入口的共同标识**：小程序与扫码两条链路只要换回的手机号一致，就归并到同一账号，
  不依赖 `unionid`。反向风险同样成立：号码被运营商回收后分配给新用户时，新用户登录会接管该账号，
  高敏感应用应额外要求二次验证或人工解绑流程。
- **小程序与扫码的账号合并依赖 `unionid` 或手机号**：小程序未绑定开放平台账号、且未授权手机号时，两边的 `openid` 不同，会是两个账号（平台无法合并，微信侧不提供映射）。
- **凭据直传形态只签发授权码**，令牌由标准授权码流程签发，因此接入方比标准流程多一次换令牌请求。
- **凭据登录不建立 IAM 浏览器会话**：没有 `sid`，不参与后通道登出广播。小程序侧令牌按 `exp` 自然过期；
  需要立即失效时，用管理员「全端下线」(`POST /api/v1/admin/users/{id}/logout`)或禁用账号。
- **凭据登录不受客户端准入策略约束**：`allowedLoginTypes` / `requireMfa` 只在 `/oauth2/authorize` 判定。
- **换码地址固定取客户端第一个回调地址**：不能逐次指定；小程序客户端要把它登记为唯一或第一条。
- **一个别名对应一套 AppID/AppSecret**：同域多个小程序请建多个别名，不要复用。
- **扩展包生效需要重启**：类无法卸载。
