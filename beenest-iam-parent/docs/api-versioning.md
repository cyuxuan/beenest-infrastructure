# API 版本演进与弃用策略

> 适用对象:所有 `/api/v1/**`、`/scim/v2/**`、`/realms/{realmKey}/**` 端点。
> 目的:让接入方知道"什么会变、什么不会变、变了给我多久"。

## 1. 版本号在哪

| 协议面 | 版本载体 | 说明 |
| --- | --- | --- |
| REST 管理/自助/门户接口 | 路径段 `/api/v1/` | 路径级主版本,同一主版本内只做向后兼容变更 |
| SCIM | 路径段 `/scim/v2/` | 跟随 RFC 7644 的协议版本,不随本平台版本变化 |
| OIDC / OAuth2 | 无版本号 | 跟随规范;能力差异通过 `/.well-known/openid-configuration` 的元数据声明 |
| SAML 2.0 | 无版本号 | 跟随规范;能力差异通过 IdP 元数据的 `KeyDescriptor` / `SingleSignOnService` 表达 |

主版本号只在**破坏性变更**时递增。新增字段、新增端点、新增可选参数都不递增。

## 2. 什么算兼容变更(不通知直接发)

- 响应体**新增**字段(接入方必须忽略未知字段,这是 JSON 的既有约定)
- 新增端点、新增可选请求参数
- 新增错误码(接入方按 HTTP 状态码兜底,不应穷举业务码)
- 放宽校验(原来拒绝的输入现在接受)
- 新增 scope、新增权限码

## 3. 什么算破坏性变更(必须走弃用流程)

- 删除或重命名字段、端点
- 收紧校验(原来接受的输入现在拒绝)
- 改变字段语义(如 `sub` 从登录名改成用户主键——**已发生过一次,按弃用流程处理**)
- 改变默认值(如令牌有效期默认值、分页默认条数)
- 改变错误响应的 HTTP 状态码

## 4. 弃用流程

| 阶段 | 时长 | 动作 |
| --- | --- | --- |
| 公告 | T0 | `CHANGELOG.md` 记录;响应头加 `Deprecation: true` 与 `Sunset: <RFC 8594 日期>`;文档标注 |
| 并存 | **不少于 6 个月** | 旧行为继续可用;新行为通过新路径或新参数提供 |
| 下线 | T0 + 6 个月 | 返回 `410 Gone`,响应体给出替代方案 |

例外:安全缺陷可以**立即**收紧,不受 6 个月约束,但必须在 `CHANGELOG.md` 的
「行为变更」表里写明原因与替代做法。

## 5. 响应头约定

```http
Deprecation: true
Sunset: Wed, 31 Mar 2027 23:59:59 GMT
Link: <https://iam.example.com/docs/api-versioning>; rel="deprecation"
```

`Sunset` 用 RFC 8594 的 HTTP-date 格式,不用时间戳——接入方不必猜时区。

## 6. 已登记的弃用

| 端点/行为 | 公告版本 | 计划下线 | 替代方案 |
| --- | --- | --- | --- |
| `offline_access` scope | 1.0.0 | 已移除 | 无替代:平台不提供离线令牌语义,改用较长 `refresh_token_ttl` |
| ID Token 携带 `permissions` | 1.0.0 | 已移除 | 从访问令牌读 `permissions`,或调 `/userinfo` |

## 7. 接入方应该怎么做

1. **不要穷举字段**:反序列化时忽略未知字段,否则平台加一个字段就会让接入方崩。
2. **不要穷举错误码**:按 HTTP 状态码分支,业务码只用于展示与排障。
3. **固定 `issuer`**:按 `/.well-known/openid-configuration` 的 `issuer` 校验,不要硬编码域名。
4. **校验 `aud`**:访问令牌的 `aud` 是本应用服务登记的「令牌受众」(默认 `urn:iam:app:{app_code}`),
   ID Token 的 `aud` 仍是 `client_id`;校验它能挡住"别人家的令牌"。
5. **区分令牌类型**:只把 `token_type=access` 的令牌当访问凭据,ID Token 不能当 Bearer 用。
6. **订阅变更**:关注 `CHANGELOG.md`,破坏性变更会同时出现在「行为变更」表里。
